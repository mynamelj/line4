# 2020Meshina 部署与维护

## 启用与文件配置

现有机型配置中，工位名称（stationNumber.json的Name）或MES工位ID（sys.json的StationID）精确配置为`2020Meshina`或`OP2020Meshina`，不区分大小写。不使用模糊的OP2020M匹配，其他工位流程保持原样。一个检测目录只配置一个啮合工位；独立PC通常只配置这一站和一把扫码枪。

启用后自动生成程序工作目录下的`configs/meshina.json`。扫码枪、MES接口、机台编号、线别和操作员工号继续使用原配置。该专用流程不读取PLC的SN、载具码、流程ID或出站数据；仅配置该站的PC跳过PLC连接、PLC轮询和PLC状态报警采集。

配置示例见`MES/SpecialStations/Meshina/meshina.example.json`：

```json
{
  "DataDirectory": "D:\\盘齿轮双啮检测系统\\结果\\统计",
  "Provider": "Microsoft.ACE.OLEDB.12.0",
  "PollIntervalMilliseconds": 1000,
  "StablePollCount": 3,
  "RequiredFields": ["Fi", "fii", "Fr"],
  "ItemNames": {}
}
```

- `DataDirectory`必须是存在且可访问的绝对路径，只扫描该目录第一层的`.mdb`文件，不扫描子目录。
- 默认每秒轮询，文件大小与修改时间连续3次稳定后读取。进站接口调用前保存目录基线，因此请求期间生成的文件不会丢失。
- 文件必须不在扫码基线/已处理清单中，创建时间严格晚于扫码时间，且文件名以`_yyyyMMdd_HHmmss.mdb`结尾。文件名时间不得早于扫码所在秒（文件名没有毫秒）；PC时间应保持正确。
- 同时发现多个候选文件时暂停自动关联。技术人员核实后，应将额外文件移出监控目录；程序会重新检查，不自动选择最新文件。
- `RequiredFields`配置不可为空的检测字段。默认Fi、fii、Fr；可以按MES项目要求追加。字段必须来自支持的20个数值列。
- `ItemNames`可填写字段到MES采集项的映射，例如`{"Fi":"MES实际项目名"}`。没有映射时使用MDB原字段名。
- 修改配置后重启生效。当前任务未完成时禁止切型和重新初始化，防止SN与配置串用。

## Access数据库引擎

无需安装完整的Access编辑软件，但必须有能被当前进程加载的OLE DB数据库引擎。默认使用ACE，启动时检查Provider注册情况，错误信息中会显示程序位数。

- x86程序使用32位引擎；64位程序使用64位引擎。不能仅按Windows位数选择驱动。
- 可安装微软提供的[Microsoft 365 Access Runtime](https://support.microsoft.com/en-US/Access/download-and-install-microsoft-365-access-runtime)，其中包含Access Database Engine；部署时需与现场已有Office安装兼容。
- 如果现场已具备可用的32位Jet引擎，可将Provider设为`Microsoft.Jet.OLEDB.4.0`并部署x86程序。这一组合已用本次提供的两份MDB副本验证；默认配置仍使用ACE。
- 不自动下载、安装或切换驱动。部署后先用样本确认连接和读取。

建议明确生成x86版本，避免AnyCPU进程位数与驱动不一致：

```powershell
dotnet build MES/MES.csproj -c Release -p:Platform=x86
```

## 数据与结果

读取`TJSHEET`的20个数值列：Fi、fii、Fr、aave、amax、amin、rm、rmmax、rmmin、WKave、WKmax、WKmin、Mave、Mmax、Mmin、dave1、dmax1、dmin1、diff、Cylindricity。

两份真实样本均为一行，前15列有数值，dave1、dmax1、dmin1、diff和Cylindricity为空。未启用的空项记录在`Measurement.EmptyFields`中并跳过上传，绝不补0；数值0本身是有效值，不跳过。缺列、空表、多行或必填列为空时不出站，继续提示处理。

`Measurement.Result`原样保存，样本中分别为`PASS`和`True`，暂不用于判断。当前MES每项和整体Result均沿用PASS规则；“出站OK”只表示MES接口成功。载具码为空、物料列表为空。上线前需要核对MES是否接受此站的数值项目名、可选空项和空载具。

## 故障恢复与记录

`data/meshina/current.json`保存当前任务、扫码时间、目录基线、固定请求数据、文件绑定和已处理清单。每件完成或人工结束后，在`data/meshina/history/`保存独立记录；原MDB不删除、不改写。该目录包含追溯数据及MES请求配置，应按现场程序数据管理，不要放入源码仓库或随程序升级覆盖。

- 等待MDB时重启：恢复原SN和原扫码时间，继续轮询。
- 已绑定数据但尚未发送：恢复后使用保存的数据出站。
- 请求发送中崩溃、超时、网络错误或响应无法识别：转为待核实，禁止自动重发。该站关闭了通用HTTP传输层重试，每次请求超时为30秒。
- MES明确返回FAIL：保留任务，可以“重试原任务”。
- 待核实：技术人员登录后查询MES当前SN记录，选择“已核实MES接收”或“已核实MES未接收”。前者恢复等待检测/完成出站，后者允许重试；操作记录进入MES日志。
- 放弃本件：技术人员先处理MES状态并确认设备不再生成该件文件，再点“异常结束本件”。这个按钮只结束本地任务，不替代MES撤销操作。
- 任务文件损坏、保存失败或恢复配置不一致：停止自动处理，不静默清空任务。由技术人员恢复存储与原配置，再重启核实MES实际状态。

## 验证

回归测试使用本地临时目录和模拟MES接口，不连接生产MES或PLC。覆盖单件锁定、并发扫码、旧文件排除、写入稳定、多文件歧义、读失败重试、原数据重传、未知响应、任务恢复、配置切换和损坏状态。

```powershell
dotnet build tests/Meshina.Tests/Meshina.Tests.csproj -p:Platform=x86
& tests/Meshina.Tests/bin/x86/Debug/net48/Meshina.Tests.exe
# 可选：传入已复制到测试目录的真实MDB，验证当前驱动。
& tests/Meshina.Tests/bin/x86/Debug/net48/Meshina.Tests.exe '完整样本路径.mdb' 'Microsoft.Jet.OLEDB.4.0'
```

部署联调仍需在工位完成一次扫码、实际啮合保存、MES自动出站，以及失败重试。当前开发机没有安装ACE，ACE连接尚未实机验证。
