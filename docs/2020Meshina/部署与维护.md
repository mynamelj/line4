# OP2020M 部署与维护

## 单工位约定

OP2020M是独立线外小站，PC只有一个工位、一把扫码枪，无PLC。程序按工位名称包含OP2020M启用专用流程，所有MES请求固定使用工位索引0，不遍历或分配工位。其余普通站仍使用原PLC流程。

该站扫码枪使用USB键盘输入，跳过串口初始化，不使用COM口参数。MES接口、机台、线别和工号配置继续使用。`configs/meshina.json`首次启用自动生成，示例见`MES/SpecialStations/Meshina/meshina.example.json`。

- DataDirectory：默认`D:\盘齿轮双啮检测系统\结果\统计`，只扫描该目录中的MDB。
- Provider：默认`Microsoft.ACE.OLEDB.12.0`。
- PollIntervalMilliseconds：默认1000毫秒。
- StablePollCount：默认连续3次文件大小和修改时间不变后读取。
- RequiredFields：默认Fi、fii、Fr，其余空数值项跳过，不补0。
- ItemNames：MDB字段到MES项目名的映射，未配置时使用原字段名。

扫码时保存时间和目录已有文件清单，之后取创建时间晚于扫码的第一个新增MDB。文件名和二维码不参与关联。只有MES进站成功才自动出站；出站失败保留原数据供人工重试。Result原样留在Measurement.Result中，本期MES整体及数值项仍使用PASS。

## 驱动

无需完整Access软件，但必须有与程序位数匹配的数据库引擎。默认ACE可以使用[Microsoft 365 Access Runtime](https://support.microsoft.com/en-US/Access/download-and-install-microsoft-365-access-runtime)。32位程序用32位引擎，64位程序用64位引擎。

本机已用32位Jet和两份真实MDB副本验证读取，可部署x86程序并将Provider改为`Microsoft.Jet.OLEDB.4.0`；默认ACE在当前开发机未安装。

```powershell
dotnet build MES/MES.csproj -c Release -p:Platform=x86
```

## 简化后的运行行为

已移除多工位路由、工位与接口配置指纹、任务文件校验、历史MDB处理清单、自动恢复和人工核实按钮。不再创建或读取`data/meshina/current.json`及history记录；旧版文件不自动删除。当前SN、扫码时间和检测数据只保存在内存中，关闭、切型或重启后清空。

保留单件互斥、文件写入稳定检查、数值读取失败提示和MES失败重试。正常生产按操作手册保持“一次扫码、一次检测保存、一次出站”，异常重启由现场人工核实MES状态。

## 验证

测试使用临时目录和模拟MES，不连接生产MES或PLC。可额外传入真实MDB副本和Provider验证数据库读取。

```powershell
dotnet build tests/Meshina.Tests/Meshina.Tests.csproj -p:Platform=x86
& tests/Meshina.Tests/bin/x86/Debug/net48/Meshina.Tests.exe
& tests/Meshina.Tests/bin/x86/Debug/net48/Meshina.Tests.exe '样本副本.mdb' 'Microsoft.Jet.OLEDB.4.0'
```

OP2020M扫码时调用FeedingCheck代替CheckIn，返回结果写入`SetHelper.resultModel[0].Result1`（OK/NG），扫码SN写入`CheckInSN`。FeedingCheck成功后才等待MDB自动出站；失败重试仍调用FeedingCheck。MES接口配置使用第一个工位的FeedingCheck地址。

USB接入：根据扫码后可直接输入文本的现场表现，按键盘输入模式接收。在消息页扫码框输入，以Enter或Tab提交FeedingCheck；输入框禁用输入法，避免SN被输入法转换。程序不监听其他应用，不按字符速度猜测扫码结束。上线时用实际扫码枪验证整码和后缀。

## 终止本次流程

意外发生时，先停止旧齿轮的检测和保存，再点击消息页“终止本次流程”。程序停止本件后续步骤，释放当前SN，显示“已终止”，扫码框清空并获得焦点，可扫描新齿轮。按钮无需管理员登录。

如果FeedingCheck或出站请求正在进行，界面提示正在终止，等待该请求返回（当前请求超时30秒）后才接收新件，避免旧响应覆盖新件。已发送的MES请求不会被撤回；如出站请求已发送，应核实MES实际记录。

新扫码会重新记录目录基线，忽略已存在的旧MDB。旧件在新扫码后才保存的文件无法靠时间区分，因此必须先停掉旧件检测与延迟保存，再开始新件。
